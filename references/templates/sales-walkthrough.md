# Sales walkthrough

Purpose: `sales-walkthrough`. Suggested target: **120 seconds**. Explicit user duration
and structure take precedence; copy this target only when no duration was supplied.

Ask only for missing context: buyer role, their use case/problem, the supported value
proposition, relevant workflow and URLs, access requirements, and desired next step.

Suggested beats (scene count is flexible):

1. Connect a concrete buyer problem to the starting screen.
2. Demonstrate the relevant workflow, anchoring narrated actions with `at`.
3. Show the result and connect it to the buyer's stated need.
4. Offer the user's chosen next step.

Example outline: a finance team needs a report for analysis → show the relevant reporting
workflow → export the report → show the verifiable result → offer a tailored walkthrough.
Use only actual product controls. Do not invent ROI, time savings, customer names, metrics,
or a next-step URL. Ask for evidence or omit unsupported claims.

Use `prerequisites` and `expected_outcomes` only for observable states. Describe what the
workflow demonstrates, not results that would require external proof. Produce a normal
`demo.json` and include the purpose, audience, outcome, target and narration in approval.
